# Engineering rules

- Business rules live in two places on purpose: `src/core` (pure, for screens and messages) and `db/schema.sql` (row-level security and triggers, the authority). Change both together and add a database test. Amounts are computed by the database (`app.quote_issue`); `src/core/money.ts` only previews them, and `tests/money.test.ts` keeps the two equal.
- Every request runs through `asUser()` as the restricted `procurement_user` role; the notification sender uses `asMailer()`. Never query as the connection owner from request code.
- Outgoing fetches (catalog pages, images) go through `createFetcher()` in `src/server/net.ts`. Do not call `fetch()` or `http.request()` on user-supplied URLs anywhere else. The demo uses `demoSupplierFetcher()` and must never reach the network.
- Notifications are written to `app.outbox` by triggers, in the same transaction as the change. Request code never builds or sends mail itself; `deliverOutbox()` sends what the database queued (after the response, and from `npm run outbox:send`).
- The demo supplier site (`public/demo-supplier/`) is generated by `npm run supplier:build` from `src/demo/supplier-data.ts`. Companies, brands, people and products are fictional; never commit data copied from a real supplier site.
- No secrets or real company data in the repository. Keep commits focused by feature. Record design trade-offs in `docs/adr`.
