## 何を確かめているか

### 業務の流れと権限（`tests/database.test.ts`、`tests/service.test.ts`、`tests/review-fixes.test.ts`）

架空の会社を毎回作り直し、各人として**アプリを通さないSQL**も実行して、データベースが拒否することを確かめます。A社の担当者は自分の拠点の依頼だけを見られ、原価・利益・メーカー名・B社メモは返りません。状態の変更は役割と拠点ごとにトリガーが検査し、見積書の金額はデータベースが原価と載せ方から計算します。

### 金額（`tests/money.test.ts`）

売値（原価に率を載せた切り上げ）と、税率ごとの消費税（1回の切り捨て）を、TypeScriptとSQLで照合します。

### カタログの読み取り（`tests/catalog.test.ts`、`tests/importer.test.ts`、`tests/review-regressions.test.ts`）

JSON-LD・Open Graph・CSV（Shift_JIS・日本語の見出し）・robots.txt の読み方と、同梱の架空のメーカーのサイト全体（一覧1＋商品23ページ）の取り込み。一部のページが読めなかった取り込みでは、読めなかった商品を外さず、全部読めたときだけ外すことも確かめます。

### 外部への接続（`tests/net.test.ts`）

社内・ローカル・メタデータのアドレスを各種の表記で拒否し、名前解決の結果も接続の時点で検査します。大きすぎる本文、展開すると大きくなるgzip、リダイレクトの繰り返し、遅い応答を打ち切ります。

### コードスキャンの指摘（`tests/code-scanning.test.ts`）

CodeQL の高リスクの指摘2件の再発を防ぐ14件。依頼フォームの回答のエラー文の判定が、文の先頭だけで一致すること（文の途中の語では一致しない）と、HTMLコメントで包んだJSON-LDを `-->` でも `--!>` でも読めること。直す前のコードでは4件が失敗することを確かめました。

### 実PostgreSQL（`tests/postgres.test.ts`）

合意の二度押し、合意と再見積の同時実行（デッドロックなし）、同時の発注での発注番号、ログイン用ロールが `SET ROLE` なしで何も読めないこと、共有DBのデモが二重に作られないこと。

### ブラウザの通し操作（`e2e/workflow.spec.ts`）

本番ビルドをデモで起動し、ChromiumとWebKitのそれぞれで、A社の依頼 → B社の質問とA社の回答 → 商品概要2行 → 2社に相見積 → 原価に20%を載せた見積書 → A社の画面とHTMLに原価・メーカー名が出ないこと → 合意 → 直送で発注 → 納期確定 → A社の「通知」の納期と合計、までを画面の操作で通します。他拠点の依頼は404、A社によるB社の操作と別サイトからの送信は403。ライト・ダークで主な10画面に axe を流し、WCAG 2.1 A/AA の違反0件。

合意の確認は、見出しの状態の札が「B社の発注待ち」に変わることで判定します（2026-10-20 に直した点：以前は「次にやること」の文で判定しており、合意する前の文「…でB社がメーカーに発注します」にも一致したため、合意の送信が終わる前に次へ進むことがありました。実PostgreSQLのデモで流したときに見つけ、直したあと70件すべて成功）。

### 画面の大きさ（`e2e/responsive.spec.ts`）

25種類の画面の大きさ（280×653 の折りたたみスマホ、568×320 などの横向きスマホ4種、タブレット、1280×720 から 3840×2160 まで）を ChromiumとWebKitで回し、ログイン・ホーム・依頼する・通知・依頼一覧・デモの全件の依頼の画面・メーカー・カタログ・管理者の4画面・見つからない画面で、次を確かめます。

- 横にスクロールしない。どの要素も画面の外にはみ出さない
- 文字が箱からはみ出さない・切れない（文字の範囲を1つずつ測る）
- ヘッダーが80px。ヘッダーの部品どうしが重ならない
- ログイン画面のヒーローの高さが「画面の高さ − 80px」で、見出し・説明・役割のボタンがすべて最初の画面に入り、互いに重ならない
- 各画面の見出しと主な操作（`data-first`：依頼する・次にやること・絞り込み・検索・最初の通知など）が最初の画面にある

文字のはみ出しの検査は、280px幅で役割のボタンの名前がボタンからはみ出していたのを目で見つけたあとに足し、直す前の画面で8件を検出することを確かめてから直しました。

### 目で確かめたこと

パソコン幅1440px・スマホ幅390px・280px・横向き568×320 を、ライト・ダークの両方、ChromiumとWebKitで撮って確かめました。動き（飛び込み・数え上げ・進み具合・紙片・画面の切り替え）は、動きを止めない設定で撮った連続画像（README のGIF）で確かめています。
