# 要件定義：備品発注ワークフロー

## 目的

チェーン店の各店舗が、本社の指定する仕入先のカタログから備品の発注を依頼し、本社が承認して見積を返し、双方が合意した時点で発注を確定する。確定した発注金額は店舗・本社の双方（と仕入先）へ通知する。示すのは「そのまま納品できる業務システムを作れる」こと。

- 業務システムとしての完成度：ログイン、店舗と本社の役割、状態遷移、見積の版管理、監査ログ、通知
- 外部サイトを安全に扱う設計：指定されたサイトから商品データを読むが、社内ネットワークには触れさせない
- 日本の実務：税込表示から税抜への換算、税率ごとの区分（10%・8%）と1回の端数処理、発注番号の連番
- 並行操作への強さ：承諾と再見積がぶつかっても、DBが片方だけを通す

## 役割

| 役割                   | 主な作業                                                                 |
| ---------------------- | ------------------------------------------------------------------------ |
| 店舗スタッフ（store）  | カタログから依頼、見積の承諾・修正依頼・取り下げ（自分の店舗の依頼だけ） |
| 本社 購買担当（buyer） | 全店舗の依頼の確認、承認して見積を送る・再見積・却下                     |
| 本社 管理者（admin）   | 購買担当の作業に加え、仕入先とカタログの管理、監査ログ                   |

## 状態

| 状態             | 次にできること                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------- |
| 下書き（カート） | 作成者が編集・依頼・破棄。本社からは見えない                                                 |
| 本社の確認待ち   | 本社：見積を送る（＝承認）／却下（理由必須）。店舗：取り下げ                                 |
| 店舗の承諾待ち   | 店舗：承諾（＝合意・発注確定）／修正依頼（内容必須）／取り下げ。本社：再見積（前の版は無効） |
| 発注済み         | 変更不可。発注番号と確定金額を双方と仕入先へ通知                                             |
| 却下・取り下げ   | 変更不可                                                                                     |

## 金額の規則

| 項目       | 規則                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| 参考単価   | 仕入先の掲載価格。税込表示なら税抜に換算（切り上げ：税抜×税率を切り捨てた税込が掲載価格を下回らない最小の税抜） |
| 見積の単価 | 本社が整数の円で決める（税抜）。数量は1〜9999                                                                   |
| 送料       | 税抜。10%の対象に含める                                                                                         |
| 消費税     | 税率ごとの対象額に対して1回だけ計算し、1円未満を切り捨て                                                        |
| 合計       | 10%対象＋10%の消費税＋8%対象＋8%の消費税                                                                        |
| 有効期限   | 今日から180日以内。期限を過ぎた見積は承諾できない（日本時間の日付で判定）                                       |

## 非機能要件

| 要件                       | 目標                                                                       | 状態                                        |
| -------------------------- | -------------------------------------------------------------------------- | ------------------------------------------- |
| 権限の権威                 | アプリの不具合があっても、他店舗の参照・役割違いの操作をDBが拒否           | 実装・テスト済み（PGliteと実PostgreSQL 17） |
| 並行操作                   | 承諾の二度押し、承諾と再見積の衝突で、状態が一つに決まる                   | 実装・実PostgreSQLで検証                    |
| 通知の確実さ               | 状態の変更と通知の記録が同じトランザクション。送信失敗は再試行             | 実装・テスト済み                            |
| 外部サイトの安全な読み取り | 社内・ローカルのアドレス、リダイレクト、巨大な応答、遅い応答を拒否         | 実装・テスト済み                            |
| 取り込みの礼儀             | robots.txt に従い、同じホストへは間隔を空ける。60ページ・500商品・80秒まで | 実装                                        |
| アクセシビリティ           | WCAG 2.1 A/AA の自動検査で違反0件                                          | axeで確認（主要5画面）                      |
| スマホ                     | 店舗スタッフがスマホでカタログから依頼・承諾できる                         | レスポンシブ対応                            |
