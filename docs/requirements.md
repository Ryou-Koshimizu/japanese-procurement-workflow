# 要件定義：備品発注ワークフロー（A社 → B社 → メーカー）

## 目的

A社（店舗をもつ会社）の拠点が、B社（購買代行）に什器・備品の調達を依頼する。B社はアプリの中でヒアリングして商品概要を決め、登録メーカーに見積を取り、利益を載せた見積書をA社に出す。A社が合意したらB社がメーカーに発注し、納期を決めてA社に知らせる。示すのは「そのまま納品できる業務システムを作れる」こと。

- 業務システムとしての完成度：ログイン、A社・B社の役割、変えられる依頼フォーム、状態遷移、見積書の版管理、監査ログ、通知
- 原価を見せない設計：原価・利益・メーカー・B社メモはDBの権限でA社に返さない
- 日本の実務：税率ごとの区分（10%・8%）と1回の端数処理、依頼番号・発注番号の連番
- 並行操作への強さ：合意と再見積がぶつかっても、DBが片方だけを通す

## 役割

| 役割                 | 主な作業                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| A社 担当者（client） | 自分の拠点の依頼だけ：依頼フォームで依頼、質問への回答、見積書に合意・修正依頼・取り下げ、納期のお知らせ          |
| B社 担当者（agent）  | 全拠点の依頼：質問・B社メモ、商品概要、メーカーへの見積依頼と回答の記録、見積書、発注、納期、お断り、メーカー登録 |
| B社 管理者（admin）  | 担当者の作業に加え、依頼フォームの項目、カタログ、メンバー、監査ログ                                              |

## 状態

| 状態             | 次にできること                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| B社の確認待ち    | B社：質問（→A社の回答待ち）／商品概要を確定（→メーカーに確認中）／お断り。A社：取り下げ                                            |
| A社の回答待ち    | A社：回答（→B社の確認待ち）／取り下げ。B社：お断り                                                                                 |
| メーカーに確認中 | B社：メーカーに見積依頼・回答や辞退の記録／見積書を送る（→A社の合意待ち）／商品概要を直す（→B社の確認待ち）／お断り。A社：取り下げ |
| A社の合意待ち    | A社：合意（→B社の発注待ち）／修正依頼（内容必須、→メーカーに確認中）／取り下げ。B社：新しい見積書（前の版は無効）                  |
| B社の発注待ち    | B社：直送かB社経由を選んでメーカーに発注（発注番号を採番、→納期の確認待ち）                                                        |
| 納期の確認待ち   | B社：納期を確定（→納期確定、A社の依頼者に納期のお知らせ）                                                                          |
| 納期確定         | 変更不可                                                                                                                           |
| お断り・取り下げ | 変更不可                                                                                                                           |

## 金額の規則

| 項目               | 規則                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------- |
| 原価               | メーカーの回答をB社が入力する（税抜・整数の円）。原価計＝Σ 原価×数量＋メーカーの送料。A社には返さない |
| 売値（率を載せる） | 単価＝ceil(原価 × (10000 + bp) / 10000)。bpは0.01%単位（100bp＝1%）、0〜30000                         |
| 売値（売値を入力） | B社が行ごとに整数の円で決める（税抜）。数量は1〜9999                                                  |
| 送料・諸経費       | A社に請求する額をB社が決める（税抜）。どちらも10%の対象に含める                                       |
| 消費税             | 税率ごとの対象額に対して1回だけ計算し、1円未満を切り捨て                                              |
| 合計               | 10%対象＋10%の消費税＋8%対象＋8%の消費税                                                              |
| 利益               | 売上計（売値×数量＋送料＋諸経費、税抜）− 原価計。B社だけに見える                                      |
| 有効期限           | 今日から180日以内。期限を過ぎた見積書には合意できない（日本時間の日付で判定）                         |

## 非機能要件

| 要件                       | 目標                                                                                | 状態                                        |
| -------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------- |
| 権限の権威                 | アプリの不具合があっても、他拠点の参照・役割違いの操作・A社への原価の返却をDBが拒否 | 実装・テスト済み（PGliteと実PostgreSQL 17） |
| 並行操作                   | 合意の二度押し、合意と再見積の衝突、同時の発注で、状態が一つに決まる                | 実装・実PostgreSQLで検証                    |
| 通知の確実さ               | 状態の変更と通知の記録が同じトランザクション。送信失敗は再試行                      | 実装・テスト済み                            |
| 外部サイトの安全な読み取り | 社内・ローカルのアドレス、リダイレクト、巨大な応答、遅い応答を拒否                  | 実装・テスト済み                            |
| 取り込みの礼儀             | robots.txt に従い、同じホストへは間隔を空ける。60ページ・500商品・80秒まで          | 実装                                        |
| アクセシビリティ           | WCAG 2.1 A/AA の自動検査で違反0件                                                   | axeで確認（ライト・ダークで10画面）         |
| スマホ                     | A社の担当者がスマホで依頼・回答・合意できる                                         | レスポンシブ対応                            |
