# 公開前のセキュリティ確認

2026-10-16、GitHubで公開する前に、リポジトリの全履歴と公開するファイルの点検と、コードの静的なセキュリティレビューを行いました。秘密の値を点検のログに出さない方法で行っています。

その後、2026-10-17 に「カートで注文する版」から今の流れ（A社の拠点の依頼 → B社のヒアリング・相見積・見積書 → A社の合意 → B社の発注 → 納期のお知らせ）に切り替えました。下の表の「今のコード」の列は、2026-10-20 時点のコードを指します。

## 公開するファイルの点検（2026-10-16）

- **秘密情報**：Stripe・AWS・GitHub・Slack・Google のキー、JWT、秘密鍵の既知のパターンを全ファイルで検索し、該当はありませんでした。形の知られていない秘密にも備えて、GitHub の Secret scanning と Push protection を有効にしています。
- **環境変数**：`.env.example` のSMTPは空欄です。`.env*` は `.env.example` 以外を gitignore で除いています。
- **コミットの作者**：全コミットの作者とコミッターが GitHub の noreply アドレスです。
- **個人情報**：メールアドレスは予約済みの `example` のドメインだけです。会社・拠点・人物・メーカー・商品・ブランドはすべて架空です。手元のファイルパスは含まれていません。
- **実在のサイトのデータ**：含みません。動作確認で読んだ実在の通販サイトのページは保存していません（[検証記録](verification.md)）。
- **画像**：架空のメーカーの商品写真は ChatGPT（OpenAI の画像生成）で作りました。文字・ロゴ・実在のブランドを入れないよう指示し、1枚ずつ目で確かめています。WebP に書き出すときにメタデータを除き（`cwebp -metadata none`）、EXIF・XMP・ICC のチャンクがないことを確かめました。AIで作った画像であることは [ADR 005](adr/005-demo-without-network.md) に書いています。
- **依存パッケージ**：CIで `npm audit signatures`（レジストリの署名の検証）と、本番の依存に高リスク以上の脆弱性があれば失敗する監査を毎回実行します。メール送信の `nodemailer` は、公開から2週間以上たった版（10.0.13）に固定しています。

## GitHubの設定

Secret scanning と Push protection、Dependabot のアラートとセキュリティ更新、CodeQL（`security-extended`）、プルリクエストでの依存関係の審査、非公開の脆弱性報告、`main` への強制プッシュと削除の禁止。GitHub Actions は全アクションをコミットSHAで固定し、既定の権限を空にしてジョブごとに必要な分だけを付けています。チェックアウトの認証情報は残しません。

## 公開しているサンプル値

`.env.example`、`docker-compose.yml`、`db/local-roles.sql` には、ローカルのPostgreSQL用のユーザー名とパスワード（`*_local_only`）があります。公開を前提にした開発用の値で、DBのポートは `127.0.0.1` にだけ開きます。**本番や共有の環境では、自分で決めた値を使ってください。** 公開デモのログイン用パスワード（`demo-password-2026`）も、公開を前提にした値です。

## 公開するソースと、動かすサービス

この確認の対象は、GitHubで公開するソースです。実際のデータを扱う運用では、認証基盤（多要素認証・SSO・パスワードの再設定）、複数台で共有するログイン試行の制限、監視とバックアップ、メーカーのサイトの利用規約の確認、メールの送信ドメイン認証を加えます（[導入前に決める条件](freelance-submission.md#導入前に決める条件)）。
