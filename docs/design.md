# 画面の設計

## 方針

業務アプリとして「いま誰の番で、次に何をするか」がひと目で分かることを最優先にし、質感はネオブルータリズムにしています。太い黒の枠線、ぼかしのない黒のずらした影、彩度の高い平塗り（黄・桃・水色・若草・薄紫・橙）、太い見出し、小さめの角。押せる物はすべて影の上に乗っていて、押すと影の分だけ沈みます。ライト・ダーク・システムに合わせる（自動）の3つを切り替えられます。

## 読みやすさと動きの設定

- 文字は地の色に対して WCAG 2.1 AA（4.5:1）以上。平塗りの面の文字は黒にしているため、ダークでも同じ色の面がそのまま使えます。
- 押せる部品は高さ44px以上。キーボードの選択は太い青（ダークでは黄）の枠で示します。
- 「視差効果を減らす」設定では、すべての動き（飛び込み・数え上げ・紙片・画面の切り替え）を止め、最初から最後の状態を表示します。「コントラストを上げる」設定では枠線が太くなります。

## 直感的に使えるようにしたこと

- 依頼の画面の上に7段の進み具合（依頼→ヒアリング→メーカー確認→見積書→合意→発注→納期確定）と、「あなたの番」かどうかと次にやることを1つだけ書いた枠を置き、その操作の場所へ移れるボタンを付けた。
- ホームの4つの数字の札のうち「あなたの番」は押せる札で、あなたの番の依頼の一覧へ移る。
- 依頼一覧の各行に、状態の札・7段の小さな進み具合・「あなたの番」の印を並べた。行のどこを押しても開く。
- B社だけに見える情報（原価・利益・メーカー名・B社メモ）は橙の「B社だけに見えます」の札と点線の枠で区別した。

## 確かめたこと

`npm run test:e2e` が Chromium と WebKit の両方で次を確かめます。

- ライトとダークの両方で主な10画面に axe を流し、WCAG 2.1 A/AA の違反が0件であること（`e2e/workflow.spec.ts`）。
- 25種類の画面の大きさ（280×653〜3840×2160、横向きスマホ4種を含む）で、全画面が横にはみ出さず、文字が欠けず、ヘッダーが80pxで、ログイン画面のヒーローが「画面の高さ − 80px」でその中身が最初の画面に収まり、各画面の見出しと主な操作が最初の画面にあること（`e2e/responsive.spec.ts`）。

テストは「視差効果を減らす」設定で動かします（動きがあると、axe が飛び込み途中の文字を測ってしまうため）。動きのある状態は、Playwright で録画した GIF（README の画面の動画）と、パソコン幅1440px・スマホ幅390px のスクリーンショットを Chromium と WebKit で撮って目で確かめました。
