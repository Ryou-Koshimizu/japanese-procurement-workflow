# 画面の設計

## 方針

透けるガラスの素材（すりガラス）を全面に使い、ライト・ダーク・システムに合わせる（自動）の3つを切り替えられるようにしています。素材の扱いは、各プラットフォームの公式の指針に合わせました。

- Apple の Liquid Glass（[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/)）：ガラスは内容の上に浮かぶ「操作と移動の層」に使い、背景の明るさに合わせて見え方を変え、透明度を下げる設定などのアクセシビリティ設定に従う。
- Microsoft Fluent の [Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)：素材は「ぼかし＋色味＋粒状感」で作る。ガラスを何枚も重ねない。アクセント色の小さな文字をガラスに直接置かない。透明効果を切る設定では単色にする。
- UI/UX Pro Max のスタイル表（Glassmorphism、Modern Dark）：ぼかし10〜24px、半透明の面、光の当たる縁、背景に色の光を置く、文字のコントラスト4.5:1以上。

## 具体的な決めごと

| 項目     | 決めたこと                                                                                                                                       | 実装                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 素材     | `blur + saturate` に、左上の光沢・縦の艶・縁のハイライト（マスクした線形グラデーション）・粒状感を重ねる                                         | `app/globals.css` の `.glass` / `.card` / `.pane`                          |
| 層       | サイドバー・スマホの下部タブ・カートの浮き窓・通知の小窓・「次にやること」が一番透ける層。表の入った内容のカードは色味を濃くして読みやすさを優先 | `--glass-clear` / `--glass` / `--glass-strong`                             |
| 重ねない | カードの中の小さな面（合計欄・入力欄・タブ）はガラスにせず、薄い塗りにする                                                                       | `--fill` / `--well`                                                        |
| 背景     | 5つの色の光をゆっくり動かす（48秒）。動きを減らす設定では止め、透明度を下げる設定では光もぼかしも消して単色の面にする                            | `body::before` / `prefers-reduced-motion` / `prefers-reduced-transparency` |
| テーマ   | ライト・ダーク・自動。選んだものはこの端末に保存し、表示前に適用するので、ダークを選んでいても白く光らない                                       | `app/theme-switch.tsx`、`app/layout.tsx` のスクリプト                      |
| 色       | ティール→シアンを操作の色にし、意味の色（確認待ち・承諾待ち・発注済み・却下）は必ず文字とアイコンを添える                                        | 状態の丸札 `StatusChip`                                                    |
| 文字     | 和文は Noto Sans JP、数字と英字は Plus Jakarta Sans。金額は等幅数字                                                                              | `--font`、`.num`                                                           |
| 操作     | どの画面も主な操作は1つ（ボタンの色で区別）。押せる部品は高さ44px以上                                                                            | `.btn.primary`、`.btn`、`.icon-btn`                                        |

## 直感的に使えるようにしたこと

- 依頼の画面の上に4段の進み具合（依頼→見積→承諾→発注）と、「あなたの番」かどうかと次にやることを1つだけ書いた枠を置き、その操作の場所へ移れるボタンを付けた。
- 依頼一覧の各行に、状態の札・4段の小さな進み具合・「あなたの番」の印を並べた。行のどこを押しても開く。
- カタログでは検索とカテゴリを上に固定し、カートに入れると画面の下にカートの浮き窓（品目数・点数・参考の合計・依頼へ進むボタン）が出る。
- カートでは右側の要約欄（合計・希望納期・メモ・依頼ボタン）がスクロールしてもついてくる。
- スマホでは下部のタブで画面を切り替え、主な操作は親指の届く位置に来る。

## 確かめたこと

`npm run test:e2e` が、ライトとダークの両方で主な画面に axe を流し、WCAG 2.1 A/AA の違反が0件であることを確かめます。テーマの切り替えが保存されることも同じテストで見ています。
