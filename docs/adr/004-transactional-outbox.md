# ADR 004：通知はトリガーが outbox に書き、別に送る

## 判断

状態が変わるたびに、変えたのと同じトランザクションの中で、トリガー（`app.order_events`・`app.maker_quote_events`）が宛先ごとの通知を `app.outbox` に書く。中身（依頼番号・商品概要・税率ごとの金額・合計・納期・発注番号）はその時点のDBの値を写したもので、送る側は計算し直さない。

| できごと             | 宛先     |
| -------------------- | -------- |
| 依頼が届いた         | B社      |
| B社の質問            | A社      |
| A社の回答            | B社      |
| メーカーへの見積依頼 | メーカー |
| 見積書を送った       | A社      |
| A社の修正依頼        | B社      |
| A社の合意            | B社      |
| メーカーへの発注書   | メーカー |
| 納期のお知らせ       | A社      |
| B社のお断り          | A社      |
| A社の取り下げ        | B社      |

A社＝依頼した拠点のA社の担当者、B社＝B社の担当者と管理者、メーカー＝登録したメーカーのメールアドレス。A社あての中身はA社に見える値（売値・税・合計）だけから作り、原価はメーカーあての発注書にだけ入る。依頼が閉じたときに開いているメーカーの見積は取り下げるが、メーカーにはメールを送らない。

送信は `deliverOutbox()` が行う。応答を返した後（Next.js の `after()`）と、定期実行の `npm run outbox:send` から呼ぶ。行は `FOR UPDATE SKIP LOCKED` で取り出し、送信中の印と10分の期限を付ける。失敗は1・4・9・16分の間隔で、5回まで送り直す。

## 理由

- 「発注は済んだのにメールが出ていない」「メールは出たのに依頼は取り消された」を起こさない。DBのコミットとメールの送信は同時に成功させられないので、コミットされた事実だけを後から確実に送る。
- 宛先の決め方と中身の作り方をDBに置くと、画面の「通知」とメールが同じ中身になる。A社あての中身に原価が入らないことも、DBのテストで確かめられる。

## 代償

- 送信は「少なくとも1回」。送った直後に止まると、期限が切れた後にもう一度送ることがある。
- SMTPを設定しない実運用モードでは、送信待ちのまま残る（画面の「通知」には表示する）。
- 送信役のロール `procurement_mailer` は outbox を読むことと送信の状態を変えることだけができ、宛先や本文は変えられない。
