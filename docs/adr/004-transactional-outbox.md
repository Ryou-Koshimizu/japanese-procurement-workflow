# ADR 004：通知はトリガーがoutboxに書き、別に送る

## 判断

依頼・見積・修正依頼・却下・取り下げ・発注確定のたびに、状態を変えたのと同じトランザクションの中で、トリガー（`app.order_events`）が宛先ごとの通知を `app.outbox` に書く。中身（発注番号・明細・税率ごとの金額・合意の記録）はその時点のDBの値を写したもので、送る側は計算し直さない。

送信は `deliverOutbox()` が行う。応答を返した後（Next.js の `after()`）と、定期実行の `npm run outbox:send` から呼ぶ。行は `FOR UPDATE SKIP LOCKED` で取り出し、送信中の印と10分の期限を付ける。失敗は1・4・9・16分の間隔で最大5回まで再試行する。

## 理由

- 「発注は確定したのにメールが出ていない」「メールは出たのに発注は取り消された」を起こさない。DBのコミットとメール送信は同時に成功させられないので、コミットされた事実だけを後から確実に送る。
- 宛先の決め方（店舗側＝その店舗のスタッフ全員、本社側＝購買担当と管理者、仕入先＝発注書の送り先）をDBに置くと、画面からも監査からも同じ規則で見える。

## 代償

- 送信は「少なくとも1回」。送った直後に落ちると、期限切れ後にもう一度送ることがある。
- SMTPを設定しない実運用モードでは送信待ちのまま残る（画面の「通知」には表示される）。
- 送信役のロール `procurement_mailer` はoutboxの読み取りと状態の更新だけができ、宛先や本文は変えられない。
