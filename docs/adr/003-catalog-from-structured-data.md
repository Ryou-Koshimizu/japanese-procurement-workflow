# ADR 003：カタログは仕入先サイトの構造化データから読む

## 判断

「指定のサイトからカタログを出す」を、仕入先のページに載っている構造化データ（schema.org の `Product` / `ItemList` / `ProductGroup` / `Offer`、なければ Open Graph の product タグ）を読むことで実現する。HTMLの見た目（クラス名や表の位置）から推測するスクレイピングはしない。

- 管理者は商品一覧ページか商品ページのURLを入れる。一覧に `ItemList` があれば、同じホストの商品ページを最大60ページたどる。
- 価格は円の整数だけ。税込か税抜かはページの `valueAddedTaxIncluded` を優先し、なければ仕入先ごとの設定に従う。「軽減税率」と書かれた商品は8%。
- 画像は取り込み時に先頭バイトで形式を確かめてコピーし、アプリから配信する。
- 構造化データを出していない仕入先はCSV（UTF-8・Shift_JIS、日本語の見出し）で取り込む。

## 理由

- 構造化データは検索エンジン向けに多くの通販サイトが載せている、意味の決まったデータで、サイトの見た目が変わっても壊れにくい。
- 見た目からの推測は仕入先ごとの調整が必要で、価格の取り違えがそのまま発注の参考価格になる。
- 画面で外部の画像を直接読むと、CSPを緩める必要があり、閲覧のたびに仕入先へ利用者の情報が送られる。

## 礼儀と安全

`robots.txt` に従い（確認できなければ読まない）、同じホストへの要求は間隔を空け、連絡先のURLを含むUser-Agentを名乗る。仕入先の利用規約で自動取得が禁じられている場合は、仕入先から提供されるCSVを使う。接続先の制限は ADR 001 ではなく `src/server/net.ts`（[脅威と対策](../security.md)）で扱う。

## 代償

- 構造化データのないサイト、ボットを拒否するサイト、ログインが必要な法人向けサイトは読めない。2026-10-16に国内の大手通販サイト2つのトップページで確かめたところ、1つはこの取り込みのUser-Agentに403を返し、もう1つはトップページに商品の構造化データがなかった（商品ページは未確認）。
- 構造化データに税率の項目はないため、「軽減税率」の表記がない食品は管理者が税率を直す（取り込み直しても上書きしない）。
