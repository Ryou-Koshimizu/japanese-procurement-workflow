# ADR 005：外部に接続しない公開デモ

## 判断

公開デモ（`APP_MODE=demo`）は、架空の仕入先「さくら備品サプライ」のサイトを `public/demo-supplier/` に同梱し、予約済みのドメイン `https://sakura-supply.example` のURLをそのファイルに対応づけて読む。取り込みの処理（robots.txt・一覧からの巡回・JSON-LDの読み取り・画像の判定）は実運用と同じで、ネットワークに出る部分だけを差し替えている。それ以外のURLは取り込めない。

架空のサイトは `npm run supplier:build` が `src/demo/supplier-data.ts` から作る。商品写真は ChatGPT（OpenAIの画像生成）で6枚ずつ格子状に作らせて切り出したもので、プロンプトは `scripts/demo-supplier/photo-prompts/` に残している（文字・ロゴ・手・人物を禁止し、全23枚を目で確かめた）。メールは送らず、送る予定だった内容を画面の「通知」に出す。

## 理由

- 誰でも触れる公開デモが任意のURLを読めると、他人のサイトへの踏み台になる。
- 実在の仕入先のデータを公開リポジトリに入れない。
- 取り込みの処理そのものは実物と同じなので、デモで見せたものが実運用でも動く。

## 公開先

Vercelで公開する（<https://japanese-procurement-workflow.vercel.app>）。サーバーレスではリクエストごとに別のインスタンスが応答し得るため、プロセス内のPGliteでは画面ごとにデータが食い違う。公開デモだけは専用の共有PostgreSQL（`DEMO_DATABASE_URL`、Neonの無料枠）を使い、1日ごと（または管理者の初期化）に全テーブルを空にして同じ手順で作り直す。初期化は勧告的ロックの下で行うので、複数のインスタンスが同時に作り直すことはない。アプリ全体は `scripts/vercel-build.mjs` で1つの関数にまとめている。

## 代償

- デモでは実在のサイトからの取り込みを試せない。手元の実運用モードで試す。
- 架空サイトの構造化データは素直な形なので、実在サイトの多様な書き方は `tests/catalog.test.ts` の例で確かめている。
