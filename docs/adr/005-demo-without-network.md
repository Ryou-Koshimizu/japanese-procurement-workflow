# ADR 005：外部に接続しない公開デモ

## 判断

公開デモ（`APP_MODE=demo`）は、架空のメーカー「さくら備品サプライ」のサイトを `public/demo-supplier/` に同梱し、予約済みのドメイン `https://sakura-supply.example` のURLをそのファイルに対応づけて読む。取り込みの処理（robots.txt・一覧からの巡回・JSON-LDの読み取り・画像の判定）は実運用と同じで、ネットワークに出る部分だけを差し替えている。それ以外のURLは取り込めない。

デモのデータは `src/server/demo-seed.ts` が作る。会社・拠点・人物・依頼フォームを入れた後は、画面と同じ処理を順に呼び、カタログの取り込み、メーカー3社の登録、7件の依頼（納期確定・合意済み・見積書の回答待ち・相見積中・質問の回答待ち・新規・お断り）までを進める。どの依頼も、実際のトリガーと通知を通ってその状態になっている。メールは送らず、送る内容を画面の「通知」に表示する。

架空のサイトは `npm run supplier:build` が `src/demo/supplier-data.ts` から作る。商品写真は ChatGPT（OpenAI の画像生成）で6枚ずつ格子状に作らせて切り出したもので、プロンプトは `scripts/demo-supplier/photo-prompts/` に残している（文字・ロゴ・手・人物を禁止し、全23枚を目で確かめた）。

## 理由

- 誰でも触れる公開デモが任意のURLを読めると、他人のサイトへの踏み台になる。
- 実在のメーカーや通販サイトのデータを、公開リポジトリに入れない。
- 取り込みの処理そのものは実物と同じなので、デモで見せたものが実運用でも動く。

## 公開先

Vercel で公開している（<https://japanese-procurement-workflow.vercel.app>）。サーバーレスではリクエストごとに別のインスタンスが応答することがあり、プロセスの中のPGliteでは画面ごとにデータが食い違う。そこで公開デモだけは専用の共有PostgreSQL（`DEMO_DATABASE_URL`、Neon の無料枠）を使い、1日ごと（または管理者の「デモを初期化」）に全テーブルを空にして同じ手順で作り直す。作り直しは勧告的ロックの下で行うので、複数のインスタンスが同時に作り直すことはない。アプリ全体は `scripts/vercel-build.mjs` で1つの関数にまとめている。

## 代償

- デモで取り込めるのは、同梱の架空のサイトだけ。実在のサイトは、手元の実運用モードで試す（[ローカル実行と実運用モード](../local-setup.md)）。
- 架空のサイトの構造化データは素直な形なので、実在のサイトのさまざまな書き方は `tests/catalog.test.ts` の例で確かめている。
