## RLSの守備範囲

RLSとトリガーは、アプリのコードの誤り（権限チェックの書き忘れ、IDの取り違え）から店舗の分離と発注の流れを守るためのものです。制限ロールとして任意のSQLを実行できる者は、リクエストの文脈（`app.user_id` / `app.org_id`）を自分で設定できます。DB接続情報そのものは秘密として管理してください。

## 対象外

- SSO、パスワードリセット、多要素認証
- 複数台構成でのログイン試行制限の共有、大量のリクエストによるDoS（前段のプロキシやWAFで制限する前提）
- 取り込み中の仕入先サイトの改ざん（仕入先のサイトが偽の価格を載せた場合、その価格が参考単価になる。発注の金額は本社が見積で決める）
- メールの到達性（SPF・DKIM・DMARCの設定はSMTPの提供元で行う）
